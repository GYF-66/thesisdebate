# 第一次使用研辩台

首页选择「用示例试一次」。这会创建一份独立练习文档，用真实的本地规则检查，不需要先配置模型。

1. 点击「开始检查」，展开一组建议，核对原文和修改。
2. 选择「接受此项」或「保留此项」。低风险格式项也可以按组确认，并撤销本批。
3. 在「排版与导出」选择文件格式。默认导出当前确认稿；预期稿含尚未接受的建议。
4. 完成一次真实导出后，引导收起。随时从「使用引导」重新打开。
5. 从「工具 → 导入文档」带入自己的 DOCX、Markdown 或 TXT 文件。练习文档与自己的文档分别保存。

## 按任务使用工具

导入自己的文档后，蓝色「下一步」引导会指向「选择规范」。点击「上传模板或规范」，Word（.docx）读取实际段落、样式继承、标题与页面设置；PDF 读取明文要求，也可从重复正文的文字层识别实际字体和字号。封面、页首或页眉可提供学校/学院名称，无依据时保留待填写状态。

上传后自动填入有依据的学校、字体、字号、行距、缩进、页边距和标题参数。蓝色表示已识别；冲突用橙色提示，展开来源后选择取值。固定磅值行距保留原单位，缺项保留可编辑默认值。选用后自动打开排版预览，核对并点击「应用全部排版」，设置会随当前文档保存。扫描 PDF 需先转换成带文字层的文件；最小值行距、复杂分节和缺乏文字依据的格式需要核对。

- **检查文档**：检查当前正文的格式；「文档助手 → 检查论文」同时检查章节与引用关系。
- **查找文献**：输入关键词、题名或 DOI，可限定年份。检索 Crossref 和 OpenAlex，只向这些服务发送检索词与筛选参数。相同 DOI 合并，缺 DOI 时按题名合并。选择结果后才加入本篇文档资料。
- **文档助手**：例如「检查论文，然后导出」「查找文献：learning analytics」「导师意见：请补充样本依据」「正文行距改为2倍」。任务按文档保存，失败后可继续未完成步骤；取消后也能续跑。正文或文档规范变化后，需要按当前版本重新运行。
- **导师与资料**：录入意见、关联原文、记录处理说明和答复；也可上传 PDF、DOCX 或纯文本资料，在资料中检索摘录。
- **内容审查**：需要在「模型连接」或「工具 → 模型设置」配置兼容服务。五个角色按实际调用报告进度，失败可重试；相同修改合并并保留每个角色的依据，冲突修改交由人工核对。

## 如何理解结果

「仅题录」表示尚未取得文献摘要或全文，题录只能用于文献身份核对；「含摘要」也不代表已经阅读全文。资料中只保存实际取得的文本、来源、检索时间和校验值。外部结果中的文字不会作为软件操作指令。

排版助手先展示字段变化，确认后才应用。数字、公式与引用的内容变化继续要求人工核对。导出预期稿是预览操作，不会把待确认建议变成已接受。

任务记录、正文、所选资料保存在本地工作区。关闭应用时会保存已有任务结果，重新打开后可续跑；未完成的模型调用会停止。模型审查遵循当前渠道的已有配置，运行中的审查继续使用创建时绑定的渠道。

## 这轮界面参考

沿用 Product Design 与 unslop 的纸张、批注方向：统一段落定位，建议详情只保留一份，收起角色日志，把真实修改差异作为主要视觉信息。交互参考 VS Code walkthrough 的任务入口、Zotero 的选择后入库和 Dify 的人工确认节点。未更改 GitHub 发布、贡献流程。

配色保留 Codex 浅色界面的简洁层次，使用柔和暖白渐变、浅灰侧栏和石墨灰按钮。修订区参考代码差异视图：原文为淡红、建议为淡绿，具体变化的字词用更深底色突出，当前修改块用淡蓝标记；加减号与颜色图例辅助区分。排版导出、字体选择、导师资料与工作台共用主题颜色。
